Apps that AI agents can write, check and run.

tinyjump is an open-source runtime. One TypeScript-shaped codebase gives you native screens on the web, Android and iOS, and the backend behind them. We built it so that a coding agent can write an app, check it, use it and measure it without gluing ten tools together.

    }

Why we built it

A typical app today is a web front end, two mobile apps, an API, a database, a realtime service, a queue, a sign-in service and a test setup. Each part has its own language, build and ways to fail. A coding agent can write any one of them well. The joins between them are where apps break, and where people spend their time.

tinyjump removes the joins. State lives in objects that save themselves. The same objects are the backend API and the source of every screen, and every screen updates when they change. The runtime draws real native widgets on each platform, checks access rules on the server, and lets tools inspect and drive everything. You write one language and use one tool.

Who it is for

Founders

  • Ship to the web, Android and iOS from one codebase, with a small team or with agents.
  • Offline use, realtime sync, access rules and audit trails are part of the runtime. They are not separate projects.
  • Open source (MIT or Apache-2.0). Run it on your own Linux server; your data stays yours.

Developers

  • Durable objects with timers, alarms and events. @server objects have live, offline-cached replicas on every device.
  • Calls made offline wait in a queue and run exactly once when the server is back.
  • Native Android Views and UIKit, laid out by one engine, with right-to-left support.
  • The core does no I/O, so runs are deterministic and can be tested without a device.

Agent-driven coders

  • tj docs hands an agent the whole language in one call.
  • tj check errors say how to fix them: 'txt' is not a field of Todo, did you mean 'text'?
  • tj mcp lets an agent inspect, tap, type, screenshot and review a running app on any platform.
  • tj bench and a size budget give numbers to optimise.

Decisions, and why

TypeScript-shaped, not a new syntaxAgents already write TypeScript. We changed rules, not syntax: one way to do each thing, and every unsupported feature has an error that says what to write instead.
Objects instead of a database plus an ORMState, timers and events sit in one place. Each change is saved and numbered, so devices resume where they left off after a lost connection.
The core does no I/OHosts do the I/O. The same core runs in browsers, phones and servers, and any run can be replayed exactly in a test.
Native widgets, not a web viewReal Android Views and UIKit controls, placed by one layout engine in the core, so a screen looks the same everywhere and can be tested anywhere.
Closed by defaultNothing can be read or called from outside without a rule next to the code: @read, @allow, caller. An independent security review shaped the design before we built it.
Plugins speak MCPExisting MCP servers (databases, payments, search) work as plugins from day one, each in its own process, with secrets kept on the server. The first plugin is an AI model, and agents built on it act only within the rights of the person they act for.
Small, and measuredA size and speed budget fails any change that makes a build bigger or an app slower, unless the budget is raised on purpose, with the reason written down.

How it is built

One owner sets the direction in a written vision that every change is checked against. AI agents build tinyjump step by step: each step comes with its tests, is measured against a size and speed budget, and is run live before it merges.

Other agents review the design and the work independently, without the builder's reasoning in front of them. That review corrected the trust design before any of it was built, and it keeps going: every correction is written down in the docs with its reason, so you can see what was planned, what was found and what was done instead.

Starting fresh

tinyjump starts without decades of legacy packages. That is a cost, and also an advantage: every library can be small, typed, tested and audited against its declared permissions before it ever runs.

Apps reach existing services through MCP plugins, fetch, typed OpenAPI bridges (tj bridge openapi), server-to-server object sync and HMAC-signed webhooks, while <Native> wraps platform views on the web, Android and iOS. The tinyjump registry (tj search, tj info, tj add, tj.lock, commit & SHA-256 pinning, trust marks and static permission audits) is live for pure-.tj libraries, agent ports and compliance packs. Teams with existing systems can run tinyjump next to them and move one piece at a time.

Where it runs

Where it is heading

  • Device capabilities (camera, location, notifications, files) and 1:1 / group voice and video calls (WebRTC) as opt-in plugins.
  • Desktop native UI hosts (macOS AppKit and Linux desktop).
  • Optional GPU graphics and 3D module (tj-gfx on wgpu) so apps without 3D stay small.
  • Registry publisher programme, sandboxed behaviour checks and Sigstore/SLSA provenance signing.

Latest

  • Registry discovery, searchable catalog and OpenAPI bridge generator. tj search and tj info query mindmakr.github.io/tj-plugins (seeded with Official money, slug, csv, validate libraries plus gdpr-eu and Saudi pdpl-sa compliance packs, nightly re-scans and community trust-mark gating). tj bridge openapi spec.json generates compile-checked, typed .tj REST clients with literal HTTPS host prefixes and verified draft registry manifests — with zero bytes added to device runtimes.
  • Turnkey mobile and AOT web packaging. tj build app.tj --android --aot --assemble generates a self-contained Gradle project and builds an installable native Android APK (531 KB for single-ABI arm64 AOT, zero AndroidX/Kotlin, env-var release signing); --ios --aot --assemble compiles and signs a zero-Xcode UIKit .app bundle on macOS (boot-verified on the iOS Simulator in CI); and --web auto-bundles the 215 KB gzipped AOT WASM runtime.
  • Golden-image diffs and compiler-free AOT builds. tj review --target <url> --golden baseline.png (or offline --golden + --actual) diffs PNG screenshots pixel-by-pixel with configurable --threshold and red-highlighted --diff output. Opt-out compiler feature builds (cargo web-aot, --no-default-features) strip the compiler out of AOT-only device runtimes: Web WASM drops 36% to 540 KB (215 KB gzipped) and Android drops 22–23%.
  • Translations, locales and pseudo-locale sweeps. Built-in t("key", { count }) with locales/*.json, CLDR plural rules and compile-time key/placeholder checks; <Format> and <Time> format numbers, currencies, percentages and dates with the host's native formatter (zero ICU data in core); and tj review app.tj sweeps every locale plus an expanded "pseudo" locale offline to catch truncation and RTL overlap before release.
  • AOT builds, UI catalog and custom native views. tj build compiles apps to validated .tjb bytecode and emits static --web bundles, standalone SHA-256-verified --linux executables and --android / --ios asset bundles. Added <Tabs>, <Icon>, <List>, <Theme> and <Native name="..." /> across the web, Android and iOS hosts.
  • Server-to-server sync, webhooks and the package registry. Servers replicate objects from other tinyjump servers (remotes.json) and exchange HMAC-signed incoming / durably retried outgoing webhooks (webhooks.json). The mindmakr/tj-plugins registry and tj add / tj.lock / tj registry check ship with commit + SHA-256 pinning, typosquat guards, trust marks and static permission audits.
  • Living-app tooling and retried external effects. Scoped operational keys (--ops observe|test|maintain), canonical app manifests (/_tj/manifest), work leases, deterministic trace testing (tj test + tj mcp record_trace), schema compatibility checks (tj check --against), @invariant atomic rollback, shadow-booted live reloads with health-gated rollback (tj reload / tj rollback), size/rate/AI caps, tj retro, and crash-stable crypto.idempotencyKey(label).
  • Milestone 1 booking app, across all four platforms. A 283-line booking app (examples/booking/app.tj) proven through three blind build/review rounds — staff publish slots, customers book and cancel with @exclusive double-booking guards, external check webhooks, keyed reminder alarms, offline queuing and full subject rights — verified live on the web, Android emulator, iOS Simulator and Linux tj serve.
  • Forms, dates, queries, per-field rules and deletion. Built-in Time arithmetic and typed date/number inputs, Class.all() live queries, this.delete(), keyed alarms (this.schedule("remind", ...)), per-field @read rules with "self" presence masking and "none" server-only fields, Form/FormInput/Actions in tj:ui, and check() validation errors that keep their field name across server RPCs and retries.
  • Personal-data flow checks, retention, per-person keys and compliance packs. Compile-time flow checking tracks @pii across functions, components and tj:ui so personal data cannot reach fetch, logs, errors or plugins without reveal(value, purpose), while letting a person view their own exportData(caller.id) on screen. Includes @retain, @legalHold, per-person encryption keys (crypto-shredded on erase), @by shared lists, tj:consent with @needs, const lawfulBasis, GDPR article 30 records (tj check --privacy --record), and extensible data-only compliance packs (tj check --compliance, tj serve --compliance).
  • Personal data, marked and masked. @pii("contact", "account") marks a field with its category and purpose. Its owner (and any readers the field names) reads it; other readers and every tool, agents included, see •••. tj privacy export and erase act on everything held about one person, erasures reach their devices like any other change, and the audit log forgets them.
  • Encrypted at rest, and secrets for apps. Set TJ_KEY_FILE and every stored object is sealed with AES-256-GCM under its own key; file names reveal nothing, and keys change without re-encrypting. Apps get crypto.randomId(), crypto.hmac() and crypto.timingSafeEqual(), backed by secure random bytes from every host. A server reachable from other machines refuses credentials over plain HTTP. On the way we fixed an older flaw: a record that could not be read made its object start empty, and its next save overwrote it. Now the call fails instead.
  • An audit log that shows tampering. Every API call, refusal, admin request, timer, alarm, agent tool and plugin call is written down: who, what, the outcome and the time taken, never values. Each line is chained to the one before with a keyed hash, and signed checkpoints can be copied off the machine. tj audit verify finds a changed, removed or reordered line, and with that copy, a history rewritten by someone holding the key. People appear as random tokens, so forgetting someone does not mean editing the log.
  • One call at a time, where it matters. Mark a method @exclusive and an object runs one such call at a time, like an actor, even across await. Three payments of 60 from a balance of 100, sent at once: one goes through instead of all three. Calls that would wait for each other fail at once instead of hanging, and an agent's tools never wait for the agent.
  • Runtime statistics. Calls, errors, refusals and work for every method on every platform, latency on servers, tj stats, and /_tj/metrics for Prometheus and Grafana.
  • Saves that reach the disk. A crash leaves the old record or the new one, and a save that fails fails the call, so nobody is told a change happened when it did not.
  • Agents that follow the rules. tj:agent turns an app's methods into tools, and every tool call is checked as the person who asked. The shop assistant can add tea for a shopper, but only restocks for staff.
  • Sign-in. Tokens from any OpenID Connect provider (Google, Microsoft, Auth0, Keycloak), API keys for agents and scripts.
  • Plugins and an AI assistant. Plugins are MCP servers in their own processes; tj:ai calls Claude with the key kept on the server.
  • Access control. Closed by default, with one-time stream tickets, audit lines and per-caller limits.
  • Apps in several files. import { Cart } from "./cart", with errors that say which import to add.
  • Calls that survive outages. Offline calls queue and run exactly once; replicas resume their change stream.
  • Right-to-left and one layout engine for Arabic, Urdu and Hebrew on every platform.
