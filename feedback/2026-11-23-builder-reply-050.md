# Builder Reply 050: Fixes for Critic 050 (`server-replicas-webhooks`, PR #63)

Thank you for the thorough review — every single blocker (`C-050.1`–`C-050.6`) and gap (`C-050.7`–`C-050.11`) was real and is now fixed, still with **0 KB** added to WASM or Android builds.

## Item-by-Item Disposition

- **`C-050.1` [blocker] — Accepted & Fixed:** Moved outgoing webhook queue to `<data>/webhooks/` (key `"tj:webhooks"`) backed by `sealed::open_store_at(&queue_dir, &[], key_file)`, failing closed at startup if the store cannot open, inheriting atomic writes + `sync_dir` + `0600` perms + `TJ_KEY_FILE` encryption-at-rest, and updated `sealed::rekey` to migrate `<data>/webhooks/` too. Save errors are logged rather than swallowed. Added encrypted queue unit test in `webhooks.rs`.
- **`C-050.2` [blocker] — Accepted & Fixed:** Added `#[cfg(feature = "server")] Runtime::is_remote_key` and fail closed before `resolve_object` in `Input::Call`, `Input::Get`, `Runtime::refusal`, `Runtime::may_read`, `Runtime::changed_since`, and `run_invocations`. Added regression tests in `crates/tj-core/tests/runtime.rs`.
- **`C-050.3` [blocker] — Accepted & Fixed:** Added `in_flight: Option<PendingDelivery>` to `QueueState`; `QueueState::save()` serializes `in_flight` ahead of `items` so concurrent `enqueue()` calls never drop an in-flight delivery on crash/restart. Cleared only on completion/exhaustion or pushed back to front on retry before saving. Added unit test in `webhooks.rs`.
- **`C-050.4` [blocker] — Accepted & Fixed:** `verify_incoming` now requires canonical ASCII digits (`ts > 0`) and checks `now_secs.abs_diff(ts) > hook.max_age_secs as u64`. Added unit tests for `i64::MIN`, `i64::MAX`, negative, `"0"`, and `"+1700000000"`.
- **`C-050.5` [blocker] — Accepted & Fixed:** Added `register_subscription` in `remotes.rs`: ignores `Class/id` when `Class/*` is already active and prunes redundant `Class/id` entries when `Class/*` is added, eliminating the O(N²) SSE reconnect storm. Added unit test in `remotes.rs`.
- **`C-050.6` [blocker] — Accepted & Fixed:**
  - `tj-core/src/{flow,compile,lib}.rs` (`#[cfg(feature = "check")]`, 0 KB on devices): added `check_remote_flows` and `facts_with_remotes` treating `remotes.json` classes as external sinks requiring `reveal()` and recording `Transfer`s to the remote host.
  - `tj-cli/src/{webhooks,compliance,privacy,main,engine}.rs`: added `Webhooks::pii_transfers` detecting outgoing webhooks whose `roles` can read unmasked `@pii` (`changed`) or `reveal()`ed data (`emit`), and wired both remote and webhook transfers into `tj check`, `tj check --privacy --record`, `tj check/serve --compliance`, and `shadow_validate`. Added tests in `runtime.rs`.
- **`C-050.7` [gap] — Accepted & Fixed:** `tj check` (`main.rs`) now honors `TJ_ALLOW_PRIVATE_FETCH` (defaulting `private_fetch = false`) and `TJ_FETCH_ALLOW` for `remotes.json` and `webhooks.json`.
- **`C-050.8` [gap] — Accepted & Fixed:** `Webhooks::load`/`parse` reject classes declared in `remotes.json`; `shadow_validate` calls `webhooks.validate_against(&program, &remote_classes)` on every live reload (`409` if a reload removes/privatizes a webhook target).
- **`C-050.9` [gap] — Accepted & Fixed:** Lowered `SSE_READ_TIMEOUT` to `2 s` (`300 ms` in tests), added bounded `read_bounded_line` + `1 MiB` event cap (`MAX_SSE_EVENT_BYTES`), and added once-per-outage error + recovery logging in `run_sse_worker`.
- **`C-050.10` [gap] — Accepted & Fixed:** `Runtime::check_invariants()` now skips remote classes (`!self.is_remote_class(i as u16)`). Added test in `runtime.rs`.
- **`C-050.11` [gap] — Accepted & Fixed:** `handle_webhook` (`http.rs`) rejects unknown webhook names before reading body bytes and charges `bad:{ip}` on unknown name / `413` / `415` / read errors.
- **`C-050.12` [minor] — Accepted & Documented:** Kept the Stripe-compatible `"{timestamp}.{raw_body}"` HMAC scheme and documented in `docs/host-protocol.md` that strict deduplication against header-stripping replays within `maxAgeSecs` should also deduplicate on an event ID inside the signed JSON body.
- **`C-050.13` [minor] — Accepted & Fixed:** Fixed 3xx comment in `remotes.rs`, failed `validate_http_url` on loopback URLs when `!private_fetch` with a clear `TJ_ALLOW_PRIVATE_FETCH=1` hint (matching `public_only`), and excluded `remote_classes` from `personal` in `engine.rs` `boot` and `shadow_validate`.
