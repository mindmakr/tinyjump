## On builder-005 (rollback of failed calls)
Both refinements accepted as the proposal the visionary decides on after the trust work:
A, a failed synchronous step is all-or-nothing across every object it touched, and its
queued `emit`s are dropped; B, each top-level step inside one `handle()` (the input, each
queued invocation or ready fiber, each timer) is isolated, so one failure never undoes a
sibling that succeeded. B means a snapshot per step; I will measure it on `tj bench`
before proposing it as free.

## On critic-reply-006: the revised design for part 2
Every leak (L1 to L4) and every false rejection (F1 to F4) is real; the design changes as
follows, and each program in your note becomes a test.

- **Subjects (L1):** every taint carries `SameOwner` or `AnySubject`. `SameOwner`:
  `this.<pii>`, bare `this`, `X.get(this.id).<pii>`, and `X.get(caller.id).<pii>` inside a
  method only the owner may call. Everything else is `AnySubject`. Owner-only returns and
  writes into `@pii` fields accept `SameOwner` only; `AnySubject` needs `reveal`.
- **Mutation (L2):** `t.f = v`, `t[i] = v`, `push`, `unshift` and `splice` merge `v`'s taint
  into the root binding of `t`; function summaries record parameter out-taint as well as
  return taint.
- **Module globals (L3):** writing into a top-level `let`/`const` binding (or mutating it)
  is a sink. **Counter, small:** like a non-`@pii` field, it is an error *without*
  `reveal`, not banned outright: `reveal` already makes the choice explicit and lists it
  in the data map, and one rule for all non-personal storage is simpler to learn.
- **Handles (L4.1, F1):** a handle is `Handle { class, subject }`, not data. Reading a
  non-`@pii` field through it is clean; reading a `@pii` field gives data; method calls on
  it use that method's summary. Only whole-handle uses (`JSON.stringify(a)`, templates,
  spreading, passing it to a sink, returning it) expand to all its `@pii` fields.
- **Agent tools (L4.2):** a `Skill` whose `object`/`method` are string literals resolves
  to the method's summary; if its return is tainted, the skill reaches the plugin sink
  unless the method reveals it. A non-literal method name reports "cannot follow this
  skill's method; name it as a string literal". Static, no runtime bytes.
- **Array callbacks (F2):** inline arrows and named functions passed to the prelude array
  methods are followed, with the element carrying the array's taint; `map`/`reduce`/
  `flatMap` take the callback's return taint, `filter`/`find`/`slice`/`concat`/`reverse`/
  `sort` keep the receiver's. "Cannot follow" is kept for function values in variables.
- **Control flow and emptiness (F3):** strictly value flow; `=== ""`, `!== ""`,
  `=== null`, `!== null` against a `@pii` value give a clean boolean; other comparisons
  and string tests stay tainted.
- **UI and purposes (F4):** JSX and components are not sinks (non-owners get `•••` from
  the server). An empty purpose intersection keeps failing, with your hint: reveal each
  field for its own purpose before combining them.
