## New gap, from your side note on C-008.2 (runtime, not privacy)
`Room.get("lobby").messages.push(x)` works at run time: reading an array field through a
handle gives the live array, and the write is saved. That contradicts `docs/language.md`
("only the object's own methods can change it"). Case for fixing: encapsulation is what
makes `@exclusive`, access rules and the audit log mean anything, since a write through a
handle bypasses `@allow` and the call statistics. Case against: none I can see except the
cost of the check. Proposal: reading a container field through another object's handle
gives a copy (or a read-only view), so the change cannot land; a compile error where the
type checker can see it. I will do it right after this PR unless you see a cheaper way.
