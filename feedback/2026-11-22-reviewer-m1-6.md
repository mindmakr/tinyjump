## Failures & Partial Passes

- **B18. Offline (2/3) — Cause: App + tinyjump (`Form.submit`)**
  - **Steps:** Signed in as Bob (`tj serve --web`), with open slot `e_off_book` and Bob's booked slot `e_off_canc`. Toggled Chrome offline, clicked `book-e_off_book`, then clicked enabled `cancel-e_off_canc`. Toggled back online.
  - **Expected:** Both queued actions flush on reconnect (`e_off_book` booked, `e_off_canc` open).
  - **Happened:** `e_off_book` booked, but `e_off_canc` stayed `booked: true` with no error. Because `book`, `cancel`, and `remove` share `Form.get("book")`, the first offline call leaves `book.busy() === true` until reconnect, causing `Form.submit` to silently drop the second press while leaving `Cancel` buttons enabled.

## App Defects

- **`tj privacy erase` orphans future slots:** Running `tj privacy erase key:carol` cleared `Slot/e_cli_erase#customer` to `""` while leaving `booked: true` (and a non-zero `alarm`), stranding the slot as unbookable by customers. Only the app's `deleteAccount()` avoids this via its manual `Slot.all()` loop.
- **Over-broad access:** `Slot.book` (`@allow("signedIn")`) lets a `staff` caller book via API after saving a `Customer` profile; `Slot.alarm` is exposed to `@read("staff")` though unused by clients; `validSlot` accepts non-integer minutes (e.g. `15.5`).

## Tinyjump Problems

- **Misleading `docs/language.md` (line 173):** Advises *"Let `customer` alone say whether a slot is booked (`s.customer !== ""`), so erasing the customer reopens it."* This fails whenever other users must see `"booked"` without seeing who booked (`@read("staff", "self")`), because non-authorized readers receive `""`. That forced duplicating `booked: boolean`.
- **`exportData` flow check & GDPR record noise:** Storing `exportData(caller.id)` on device-local `Screen` forced `reveal(data, "booking")` (`app.tj:171`), which also causes `tj check --privacy --record` to list `app.tj:171` under *"Where it is let out"* — and would break if PII fields spanned multiple purposes.
- **No server-private fields on readable objects:** On `@read("anyone") object Slot`, internal `alarm` cannot hide from all remote callers, so it leaks via `@read("staff")`.
- **RPC drops `check()` field names:** `docs/language.md:148` notes server refusals omit `.field`, forcing every form to call validation twice (client + server).
- **Doc gaps:** `GET /api/whoami` returns `{"ok":{"id":...,"roles":[...],"dev":false}}`, not `{ id, roles }` (`docs/access-control.md:241`). `/_tj/input` returned `HTTP 400` on `{"id":"publish","event":"onPress"}` with no documented schema in `docs/language.md`.
